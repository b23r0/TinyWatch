TinyWatch 通过浏览器监控本机和远程服务器。采集器、HTTP API、HTML、CSS 和 JavaScript 都在 `tinywatch.py` 中，只依赖 Python 标准库，无需安装第三方包或下载前端资源。

支持 Windows、Linux、macOS 和其他 Unix 系统。界面适配桌面和手机，提供深浅主题，以及英语、中文、日语、法语、俄语、德语六种语言，默认英语。

## 快速启动

```bash
git clone https://github.com/b23r0/TinyWatch.git
cd TinyWatch
python3 tinywatch.py
```

Windows 使用 `py -3 tinywatch.py`。

打开 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。首次启动时，输入服务终端打印的设置代码，再设置至少 10 个字符的管理员密码。设置完成或服务重启后，代码失效。

需要 **Python 3.10 或更新版本**，无需构建。

## 功能

| 项目 | 内容 |
| --- | --- |
| 资源指标 | CPU 总体与各核心、内存、磁盘分区、网络速率与网卡选择、系统负载 |
| 主机信息 | 处理器、系统与内核版本、开机时长、内存容量、当前会话 |
| 进程 | CPU、内存、状态，以及平台支持的网络活动 |
| 事件与 DNS | SSH/RDP 登录记录、DNS 缓存，受系统接口和权限限制 |
| 面板 | 多主机、多指标卡片，拖拽排列，移动端访问 |
| 历史 | 自定义日期时间、坐标轴、鼠标/触屏/键盘查看数值、采集断点 |
| 告警 | 阈值、历史基线、确认、恢复、触发上下文 |
| 调查 | 联动图表、变化时间线、备注、离线 HTML 报告 |
| 服务 | HTTP/HTTPS、TCP 与 TLS 证书探测、Webhook 通知、维护窗口 |
| 定时任务 | 开始/成功/失败上报、运行时限、执行记录与恢复通知 |
| 诊断 | 采集错误、样本年龄、线程状态、写盘失败、通知积压 |

前台页面每 2.5 秒刷新，后台标签页每 30 秒刷新。服务端每分钟保存资源历史并评估资源告警，关闭浏览器后仍继续。慢采集器独立刷新：进程每 10 秒，磁盘和主机详情每 30 秒，登录记录和 DNS 每 60 秒。

## 远程主机

1. 在每台主机运行 TinyWatch，通过 `--host` 和 `--port` 设置中心实例可访问的地址。
2. 登录远程实例，在**资产**中复制代理令牌。
3. 在中心实例的**资产**中添加名称、地址和令牌。`192.168.1.10:8765` 这样的地址使用 HTTP，也可填写 HTTPS URL。
4. 为该主机添加监控卡片。

主机独立采样，最多八项并发，每台主机最多一项请求。页面活跃时成功节点约每五秒更新，无人访问时每分钟更新；失败退避最长五分钟，修改配置后重置调度。缓存保留源样本时间，慢请求不会延迟已完成节点的结果。

每个节点使用一个共享令牌。中心实例通过 `X-TinyWatch-Token` 请求头访问 `/api/agent/metrics`，并保存自己的历史。HTTP 明文传输令牌，适用于可信网络；HTTPS 验证证书。代理请求不跟随重定向。

最多支持 **16 台远程主机**和 **32 张面板卡片**。

## 告警与调查

打开**告警**查看事件或修改规则。默认规则覆盖所有主机：

| 指标 | 触发条件 | 恢复条件 |
| --- | --- | --- |
| CPU / 内存 | 超过 90%，持续 3 分钟 | 低于 85% |
| 磁盘 | 最满分区超过 90%，持续 5 分钟 | 低于 85% |
| 离线 | 无法访问，持续 2 分钟 | 恢复访问 |

资源规则恢复后冷却五分钟。规则也可监控带宽、负载、样本年龄，或指定某个磁盘分区。旧代理不提供分区详情时，使用汇总磁盘占用。

历史基线使用此前 24 小时的原始样本，排除最近 10 分钟，至少需要 30 个样本。触发值为 `中位数 + max(最小增量, 3 × 1.4826 × MAD)`，恢复使用增量的 70%。事件期间冻结基线；缺失数据不会被视为恢复。

事件在重启后保留，确认不会关闭事件。最多保留 32 条规则和 1,024 个事件；达到上限时，较早的已恢复事件可能在保留期限前被清理。

**调查与回放**将资源图表放在同一时间轴上。可选择主机、分区和日期时间段，添加发布或维护备注，导出独立 HTML 报告。报告包含观测数据，不包含凭证和面板设置。

上下文记录 CPU 占用最高的三个进程、近期可读登录记录、DNS 数量/来源和采集错误。时间线记录观测到的重启、系统/网卡/分区变化及新登录记录。这些是采样结果，不是完整审计日志；时间线中的登录时间表示 TinyWatch 首次发现该记录的时间。

### 变更前后对比

在**调查与回放**中，把光标移到部署标记或其他变更时间，选择**以光标时间对比**。可选择前后各 5、30 或 120 分钟，比较资源样本中位数与峰值、服务平均耗时与失败检查次数，以及事件触发和恢复情况。

资源统计只使用原始分钟样本，排除压缩后的极值点。百分比指标的差值表示百分点。两侧分别显示观测覆盖率，低于 80% 或后一个窗口尚未结束时标记为依据不足。服务统计包含失败检查，只使用完整落在窗口内的五分钟桶；覆盖率按桶内检查的观测跨度计算，不表示在线率。指标变化是排查线索，不能证明部署与故障存在因果关系。

### 故障前后记录

在设置中开启**本机故障前后记录**，默认关闭。开启后，用有上限的内存缓冲保存本机两秒资源样本；本机事件触发时，保存触发前最多五分钟并继续记录两分钟。事件卡片提供查看入口，图表共用光标，进程表显示进程采集器原来的采样时间。

记录器复用现有采集器和缓存，进程仍按十秒刷新，磁盘仍按三十秒刷新，不会为每帧额外执行进程采集命令。片段包含资源值（磁盘取占用最高的分区）、CPU 占用最高的三个进程及采集错误名称，不包含 DNS 条目或登录记录。

内存缓冲最多 150 帧，编码样本最多 300,000 字节。持久化最多 16 段，每段最多 211 帧，存储预算为 2 MiB，并受历史保留期限限制；达到上限时删除最旧片段。覆盖率表示计划中的七分钟窗口里已记录的时间跨度，缺失指标保持图表断点。记录器最多每三十秒保存一次，其他数据库写入也可能保存这些帧。正常退出会停止并保存片段，异常终止可能丢失最近的帧。远程事件仍保留原有触发上下文。

### 规则试算

在规则编辑器中选择日期时间段，点击**试算规则**，查看触发次数、有观测依据的持续时间及无法评估的时段。试算不保存规则、不创建事件、不发送通知，也不请求远程指标。

仅评估保留的原始样本。压缩后的极值不能还原持续超阈值过程，视为未知。基线只使用当时之前的数据并排除前十分钟，模拟事件期间冻结触发基线。离线和样本过期规则没有保存决策历史，暂不支持试算。因此，七天图表有数据，并不代表七天都能用于试算。

一次只运行一项试算，时间段最长七天。基线模式最多评估 3,000 个原始样本，固定阈值最多 80,000 个，超过时请选择较短时间段或单台主机。各主机合计最多返回 200 个事件。缺测会使持续时间不完整，结果不是过去告警的精确还原。

### 磁盘容量趋势

打开磁盘详情，查看分区每日增长与预计剩余天数。使用近七天数据，要求至少四天各有十二个不同小时的样本，总跨度不少于三天；增长速度取各日末尾样本间增长速率的中位数，并检查趋势一致性。

容量变化、超过六小时的缺测、样本过期、数据不足、趋势不稳定或预计时间超过一年时，不显示剩余天数。持平或减少的占用单独显示。预测假设当前趋势持续，不代表预留容量或承诺。Unix 主机还会显示 `statvfs` 可提供的 inode 占用。

## 服务探测与通知

打开**服务监控**，可配置最多 24 项 HTTP/HTTPS、TCP 或 TLS 证书监控。探测由**中心实例所在主机**执行，关联主机只决定事件归属和维护范围。

- 间隔 30–3,600 秒，套接字超时 1–10 秒，连续失败 1–10 次触发事件；一次成功即恢复。
- TLS 证书检查验证域名和证书链，显示到期日期，可选择提前 7、14 或 30 天提醒。证书无效时检查失败，不展示未经验证的到期信息。沿用服务的失败次数、维护窗口和通知设置。
- HTTP 检查预期状态码，可在前 64 KiB 内匹配 UTF-8 文本，不跟随重定向。TCP 仅检查连接能否建立。
- 最多四项并发，错过的轮次跳过。每项探测使用临时子进程，总时限为配置的套接字超时加两秒，包含进程启动、DNS 解析和响应读取。资产请求总时限为十二秒，最多占用八个槽位。
- 改名称保留历史；修改间隔、超时和失败阈值会重置待确认失败次数；停用会关闭活动事件。更换目标、协议、主机或匹配条件会重置该项历史。
- 图表显示近 24 小时的平均探测耗时与采样成功率，失败探测也参与统计。这不是按时间加权的可用率。每项最多保留 2,048 个五分钟时间桶，同时受全局保留期限限制。

服务设置使用版本号。其他会话保存了更新的设置时，需要刷新后重试。配置写盘失败时，内存中的候选配置会回滚。

### Webhook

**通知**页支持接收 JSON 的通用 HTTP/HTTPS 接口，默认关闭。载荷包含事件和状态变化，不包含凭证、进程或登录上下文。

持久队列最多 128 项，退避重试最多五次，投递前检查 24 小时过期时间。重启可能重复发送已成功的请求，接收端应按 `event_id` 去重。界面显示投递状态及队列丢弃提示。Webhook URL 可能包含密钥，会保存在配置文件中。

### 维护窗口

可为一台或全部主机配置最多 32 个一次性窗口，每个最长 30 天。维护期间继续采集和记录事件，暂停通知。结束时仍活跃的事件会通知，维护期间已经恢复的事件保持静默。已发起的请求无法撤回。

### 定时任务

在**服务监控 → 定时任务**中添加任务，配置预期周期（1 分钟至 30 天）、宽限期（0 至 7 天）及最长运行时间（1 分钟至 7 天，默认 60 分钟）。任务沿用现有事件、维护窗口和通知设置。TinyWatch 记录上报，不执行任务，也不解析 cron 表达式。

向 `POST /api/heartbeat` 上报，`X-TinyWatch-Heartbeat` 请求头填写任务令牌，每次执行使用一个唯一的 `run_id`：

```json
{"event":"start","run_id":"backup-20261002-01"}
```

```json
{"event":"success","run_id":"backup-20261002-01","duration_ms":1234,"message":"备份完成"}
```

失败结束时，使用同一运行编号上报 `"event":"fail"`。开始和失败上报必须提供运行编号。结果说明可选，最多 240 字，不会自动采集命令输出。省略耗时时，从服务端接受开始上报的时间计算；只有结束上报、没有开始记录时记为零。

执行失败或超出运行时限会触发事件，成功上报会恢复任务事件并重置预期成功期限。存在运行中的执行时，按各自运行时限检查；没有运行时，按成功上报周期检查。开始执行不会恢复已有事件。重叠执行会显示标记，每个任务最多同时运行四次。

可展开表格查看近期执行，每个任务最多保留 50 条，并受保留期限限制，保留运行中的条目。同一仍被保留的编号重复上报相同状态时不会重复计数；已结束记录的冲突结果会被拒绝。超时记录允许接受迟到的成功或失败，并保留超时标记。编号被清理后不再提供去重。

旧格式 `{"duration_ms":123}` 仍表示成功，每次接受都会增加一条独立完成记录。令牌错误返回 403，上报格式错误返回 400，保存失败返回 503，可重试。重启后会根据持久化的开始时间检查运行超期。

## 数据与备份

**设置 → 下载备份**可在服务运行时导出一致的 ZIP，包含两代索引及其引用的历史文件，也包含已保存的凭证。压缩在数据锁外进行，归档完成前相关分片不会被清理。同一时间只允许一个浏览器导出。

通过命令行导出时，先停止该实例：

```sh
python3 tinywatch.py --data ./data/data.json --backup ./tinywatch-backup.zip
```

恢复时指定一个**尚不存在的新目录**，其上一级目录须已存在，然后启动恢复后的实例：

```sh
python3 tinywatch.py --restore-backup ./tinywatch-backup.zip --data ./restored/data.json
python3 tinywatch.py --data ./restored/data.json
```

恢复会先校验文件名、清单和分片校验和，再发布目录；目标目录已存在时拒绝恢复。归档解压后总大小上限为 512 MiB，最多 750 个文件，单索引最多 8 MiB，单分片最多 128 MiB。更大的数据目录使用下文的停机目录备份方式。ZIP 备份没有加密。

历史查询在锁内取得待保存数据快照，在锁外读取已提交分片。分片缓存最多八个文件，按估算的对象开销控制在 32 MiB 内。配置更新复用不变的历史行，心跳更新只复制对应任务的历史桶。启动时仍载入保留的历史数据，用于压缩和基线评估。

资产诊断区分初始化、连接失败、数据过期和正常状态，并显示连续失败次数、下次尝试时间。首次请求完成前，离线规则将初始化节点视为未知。

配置、任务执行和有上限的故障片段保存在 JSON 索引中。资源样本、进程上下文和服务时间桶按日存入 `<数据文件>.history/` 下的 JSONL 文件。普通保存只排序和编码变化的日期，清理、压缩及删除监控也会标记受影响的日期。查询读取选定日期，并合并尚未提交的样本。先写分片，再原子替换索引；上一版索引保存在 `<数据文件>.bak`。清理时保留主索引或备份仍引用的分片。

**备份前停止 TinyWatch，再一起复制 JSON、`.bak` 和完整 `.history/` 目录。** 文件包含令牌、主机观测信息和配置，应限制访问。

旧 schema-1 的内嵌历史和早期分片索引都会自动读取，下一次保存时写入格式 2，旧版程序会拒绝读取该索引。不要使用迁移后的数据直接降级。启动时检查分片校验和；损坏时从有效备份恢复，没有有效备份则停止启动。

保留期限可设为 **1、3、7、14 或 30 天**，默认 7 天。缩短期限会清理主索引和备份中的过期历史。

| 数据年龄 | 保留方式 |
| --- | --- |
| 最近 24 小时 | 原始分钟样本 |
| 1–7 天 | 每五分钟保留首、尾、最小值和最大值 |
| 超过 7 天 | 每小时保留首、尾、最小值和最大值 |

保留值使用实际采样时间。图表保留采集断点，每次查询最多返回 1,200 个点。较早样本无法还原每一分钟或峰值的精确持续时间。历史仍加载到内存供查询和基线使用，分片减少重复写盘，不降低历史内存占用。每个数据文件只能由一个 TinyWatch 进程使用。

## 配置

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `--host` | `127.0.0.1` | 监听地址 |
| `--port` | `8765` | HTTP 端口 |
| `--data` | `~/.tinywatch/data.json` | JSON 索引路径 |
| `--secure-cookie` | 关闭 | 反向代理提供 HTTPS 时，为会话 Cookie 添加 Secure 标志 |
| `--backup ZIP` | — | 导出已停止实例的备份后退出 |
| `--restore-backup ZIP` | — | 校验并恢复到新数据目录后退出 |
| `--version` | — | 显示版本后退出 |

```bash
python3 tinywatch.py --port 9000 --data ./tinywatch-data.json
python3 tinywatch.py --host 0.0.0.0 --port 8765
```

也可用 `TINYWATCH_DATA` 指定数据路径，`--data` 优先。

### 后台任务恢复

诊断显示线程进度、重试次数、最近异常类型及占用/超期请求槽位。十分钟内最多重试三次并退避，第四次失败后停止，需重启服务。可能包含目标或凭证的异常消息不会暴露。资产与服务的探测子进程超时后会终止并回收；替代线程池等待旧请求释放槽位。Webhook 投递仍使用套接字超时，没有子进程总时限。

## 平台与部署说明

- 按平台调用可用的 PowerShell、`ss`、`journalctl`、`who`、`netstat` 等原生命令，它们不是 Python 第三方依赖。
- 进程网络速率目前依赖 Linux `ss` 的计数和权限，其他平台可能只显示连接数量或不提供速率。
- 登录记录和 DNS 缓存受系统接口和权限限制，部分系统使用 hosts 文件作为 DNS 回退来源。面板为空不能证明没有发生事件。
- Windows 没有 Unix load average，负载面板使用 CPU 参考值。
- 内置服务使用 HTTP，默认只监听本机。在可信网络外访问时，通过 TLS 反向代理并启用 `--secure-cookie`，后端保持本机监听并限制访问。TinyWatch 不信任转发地址头，代理应自行处理客户端登录限流。
- 密码使用加盐 PBKDF2-HMAC-SHA256 哈希。请勿在问题报告中提交设置代码、密码或令牌。
- HTTP 连接限制为 10 秒无活动超时和 32 个并发请求，不是 DNS 解析或持续慢速传输的总时限。

## API

| 路由 | 认证 / 用途 |
| --- | --- |
| `GET /api/status` | 设置与会话状态 |
| `POST /api/setup` | 使用设置代码创建管理员密码 |
| `POST /api/login`、`POST /api/logout` | 登录 / 登出 |
| `GET/POST /api/config` | 会话；资产、卡片、主题和保留期限 |
| `GET /api/metrics`、`GET /api/history` | 会话；实时指标和历史样本 |
| `GET/POST /api/alerts` | 会话；规则、事件、确认 |
| `GET/POST /api/services` | 会话；探测、任务、维护和通知；保存需提交当前 `revision` |
| `GET /api/investigation` | 会话；主机及 `start`/`end` 时间段，可选 `partition` |
| `POST /api/annotations` | 会话；添加 `{node, timestamp, message}` 或删除 `{action: "remove", id}` |
| `GET /api/diagnostics` | 会话；主机与监控程序健康 |
| `POST /api/alerts/preview` | 会话；`{rule, start, end}`，只读历史规则试算 |
| `GET /api/capacity?node=local` | 会话；分区容量预测 |
| `GET /api/agent/metrics` | `X-TinyWatch-Token`；本机指标 |
| `POST /api/heartbeat` | `X-TinyWatch-Heartbeat`；任务成功上报 |

历史查询示例：`/api/history?node=local&metric=cpu&range=24h`。

预设范围：`1h`、`6h`、`24h`、`3d`、`7d`、`14d`、`30d`。自定义范围用 `custom`，并提供 Unix 秒级时间戳 `start`、`end`，不能超出保留期限。磁盘查询可传入当前指标中的 `partition=<id>`，不传则显示汇总占用。
